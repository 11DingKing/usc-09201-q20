# 隐私设计

目标：**个人轨迹不得被还原**。系统从数据边界、存储、发布三个层面保证只处理聚合信息。

## 1. 接入边界：个人数据整体拒绝

- 所有接入负载深度扫描个人级字段（证件号、姓名、电话、人脸、车牌、轨迹、成员名单等），命中即整批拒绝（HTTP 422 `person_data_rejected`）。
- 接口 schema 只接受聚合计数（人数、窗口、分区），没有承载个人标识的字段位置。

## 2. 存储：不可关联、不可还原

- **团体标识按日散列**：团体号以每日随机盐的 HMAC 入库，原始团体号不落盘；日切后旧盐丢弃，跨天无法关联同一团体，历史键不可再延展。
- 存储内不存在任何个人级记录，因此也没有任何可拼接出个人时间线的材料。
- `GET /v1/privacy/report` 与演练检查会对存储快照做禁止字段扫描与团体键格式校验。

## 3. 发布：k-匿名

- 对外视图（分区状态、点位人数）对 0 < n < 5 的小计数一律抑制（返回 `null` 并标记 `suppressed`），防止小团体在稀疏点位（如水源点）被单独识别。
- 0 与 ≥5 的计数正常发布；管理方与经营者看到的是同一套聚合视图。

## 4. 留存与替换

- 当前为内存存储，进程退出即清空；替换为持久化实现时，应沿用同样的清洗后结构（聚合窗口 + 散列团体键），并为流量窗口与在店历史设置短保留期（建议 ≤24 小时）后滚动聚合。
