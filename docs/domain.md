# 森林游客承载预警领域约定

项目面向集体林权改革与林下产业协作场景，业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够追溯到采用的数据版本。

## 数据版本与追溯

- 存储版本号 `version` 单调递增，每次变更写入审计日志（类型、引用、时间）；所有对外响应携带 `data_version`。
- 住宿上报以 `report_id` 幂等，同一酒店同一住宿日的新报告**取代**旧报告（含其团体分量）；入口批次以 `batch_id` 幂等；阈值调整以 `override_id` 幂等。重复投递返回 `duplicated: true` 且不改变数据版本。
- 入口计数按 `occurred_at` 归属营业日（UTC+8）：迟到批次补入发生日，不重复计入到达日；到达与发生时间差超过 5 分钟标记为迟到并计入数据质量提示。

## 分区负荷与等级

- 分区负荷 = 在店住宿净额 + 当日净入园（入 − 出，下限为 0）。
- 团体拆分入住：各酒店按 `token + members_at_property + declared_total` 上报分量；同一团体同一住宿日跨店分量求和，超出申报总量的部分视为重复申报并按分区占比扣减，同时产生数据质量告警。团体凭证只存哈希（见隐私节）。
- 有效阈值 = min（基础阈值， 窗口期内的临时下调）；窗口到期自动恢复，恢复后由惰性重估驱动等级回落。
- 等级：正常 / 关注 / 预警 / 管制，进入线 0.75 / 0.90 / 1.00，退出线 0.70 / 0.85 / 0.95。升级立即生效；降级须跌破退出线且距上次变更满足最短驻留（默认 10 分钟）。比率在阈值附近波动时等级保持稳定。
- 告警仅在等级迁移时发布一条通知（issued / escalated / downgraded / resolved），等级不变不重复推送，解除只发生一次。

## 角色与可见性

- `device`：入口计数批次与心跳；`hotel`：住宿在店上报；`operator`：分区压力、等级与经营建议（均为聚合结果）；`manager`：全部接口，含阈值调整、步道状态、演练与隐私审计。
- 酒店级明细、原始批次与审计日志不对外暴露；经营者只能看到分区聚合与替代建议。

## 隐私

- 不采集、不保存个人标识；入报字段实行白名单，未约定字段一律拒绝。
- 团体凭证以 `sha256(盐 + 住宿日 + 凭证)` 落库：当日可用于拆分去重，跨日不可关联，原始凭证不保存，个人与团体轨迹不可还原。
- 入口计数为匿名聚合量（进入/离开人数），不含任何个体标识。
- `GET /privacy/audit` 扫描全部已存记录，发现个人标识字段或证件号/手机号即报告违规；联合演练将隐私审计通过作为验收条件之一。
